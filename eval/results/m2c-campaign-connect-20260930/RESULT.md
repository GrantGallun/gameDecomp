## What was connected

The question was whether the earlier m2c byte-address/store-view experiment could supply usable inputs to the campaign, rather than whether it immediately matched the original object. The twelve already exposed DEV functions were reused in their original order, with no outcome-based filtering and no held-out overlap.

`probe.py` temporarily wraps `binary_type_draft.variants`: it first keeps the ordinary candidates, then appends distinct redrafts produced with the existing experimental m2c lifting adapter. It retains both syntax spellings and the existing stride-redraft behavior. Appended reports cite their ordinary source parent, binary context evidence, normalized assembly digest, preprocessing identity, address/store-view observations and expression/instruction sidecars.

The experiment calls the actual `completion_campaign._intake(..., binary_type_only=True)`, including placeholder handling, compiler-admission recovery, seed selection, frontier retention and residual construction. Its scorer is the unchanged `workspace.score`, using the actual matching helper, target-specific IDO recipe and strict frontend checker. The helper is copied into each private WSL workspace; only its project-root anchor is changed to the real toolchain location. Bootstrap returns that isolated workspace instead of the game's shared workspaces. Model calls and assisted draft/header adapter entry points are disabled in the process.

All builds and workspaces live on the native WSL filesystem. Attempts and parent edges go into a private database with zero evidence and inference rows. No reference C, existing `base.c`, game context source or held-out answer is supplied to generation. Project headers remain build-check inputs; generated m2c contexts use the existing binary-derived/public-only route. All artifacts are training-ineligible.

## Measured campaign behavior

`drawMenuSpriteClipped` and `drawMenuSpriteWithAlphaClipped` each require six attempts in current intake and still have no compiler-passing seed. Connected intake makes four attempts per function and selects the byte-address valid-syntax draft, which passes both compiler and strict frontend. Their ordinary drafts are still attempted and logged before the alternatives. The connected valid drafts have scores 59.085 and 43.352 respectively; scores are diagnostics, not correctness evidence.

The remaining ten functions have identical selected source hashes, the same valid-seed status and the same compiler-attempt count between arms. The byte adapter adds no distinct candidate on these functions. Their ordinary candidate lists remain the prefix of the connected lists. This is a retention result on these inputs, not a guarantee for arbitrary functions.

The complete comparison uses 48 native compiler attempts. Every attempt, including admission failures, is logged by the actual campaign scorer. `verify.py` passed its audit of the database, parent edges, selected and retained source retrieval, generation reports, frontend source binding and all 26 compiled object certificates. All certificates remain non-exact. The native byte-address and provenance fixture suite also passed all **14 tests**. Expression sidecars retain their partial-provenance limitations; they are recorded in intake receipts, and this test does not make downstream repair prompts consume them automatically.

## Connection failures preserved

The first launch pointed at the pointer-return artifact directory, which lacked the original selection manifest. It stopped before any compiler invocation. The next run used the original selection and made one logged current-intake compile before the temporary wrapper exposed a duplicate-report bug: unchanged C was reported as a child of itself, and intake could not resolve that unscored parent.

The experimental wrapper now records unchanged output as a duplicate without a candidate source hash or parent edge. Distinct alternatives keep ordinary-parent lineage. The completed run exercises both cases, and the audit verifies no self-parent edge and that both connected candidate lists preserve their originals. That failed one-attempt run and its code snapshots are retained under `portable/failed-connection/`; including it, this work performed **49 logged native compiler attempts**, with 27 compiled certificates audited. No production generator was edited to fix this harness error.

Native artifacts are at `/home/grant/decomp/experiments/m2c-campaign-connect-20260930-v3` and the failed `-v2` run. Local copies are under `portable/`; preregistration, code snapshots, sources, objects, diagnostics, generation sidecars, private attempt DBs and comparison receipts remain available there.

The code snapshots retain their exact preregistered hashes. After the completed run and initial audit, the shared workspace's `completion_campaign.py` changed from LF to CRLF without any text change. The final audit reports that newline-only difference explicitly, requires otherwise identical code, and continues to validate the original snapshot bytes against their recorded hashes. This probe did not write that production file.

## Decision and limits

This test supports developing the byte-address route as an additional campaign candidate generator: it survives actual intake, clears the intended validity blockers and produces retained repair seeds with preserved parent/evidence records. It also identifies duplicate handling as a concrete requirement of the eventual implementation.

It does not establish broader generalization, semantic equivalence, lower total campaign cost or additional campaign matches. Connected intake performs additional m2c translations even on unchanged inputs; only compiler-attempt counts were compared, not total generation/repair time. No repair steps after intake were run, no model was called and no whole-ROM function was replaced. The ten unchanged controls do not exercise new address fallback behavior. A separate broader positive panel and a fixed-budget repair continuation would test those remaining questions. The adapter and connection remain experimental.
