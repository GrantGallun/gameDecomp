# Own disassembly front end, stages 1-3, on SBK1 (2026-10-03)

The stages read only `~/decomp/sbk1/snowboardkids.z64`. The reference decomp (ELF, link map, C source) is read
afterwards by `disasm.grade` and only to grade. Reproduce:

    ~/decomp/sbk1/.venv/bin/python -m disasm.run --rom ~/decomp/sbk1/snowboardkids.z64 \
        --grade-repo ~/decomp/sbk1 --out eval/results/disasm-frontend-20261003/receipt-sbk1.json

`receipt-sbk1.json` (gitignored; regenerable) has stage hash `0c60b310…569ae`. It runs in about 3 s.

## Segments and code/data split

| | ours (ROM only) | reference yaml |
|---|---|---|
| boot segment | ROM 0x1000-0xE35C0 at 0x80000400 | entry 0x1000 + main 0x1050..0xE35C0 at 0x80000400 |
| CPU .text end | ROM 0xB19D0 | last `c`/`hasm` subsegment ends 0xB19D0 (`textbin` rsp/ follows) |
| data start | ROM 0xB3CF0 (lowest CPU load/store) | first `.data` subsegment 0xB3CF0 |
| non-CPU entries | 0xB19D0, 0xB1AA0, 0xB28C0 | rsp/rspboot, rsp/aspMain, rsp/f3dlx |

Only one segment exists to find. Everything else in SBK1's ROM is assets at segmented addresses, so this does not
test overlay discovery.

## Function boundaries (CPU .text, 2,126 reference functions)

| | exact (start+size) | other |
|---|---|---|
| spimdisasm alone, unseeded | 1,941 | 162 size off by trailing alignment nops; 20 extra starts; 4 missed |
| + padding split | 2,111 | |
| + seeds (`isAutogenerated=True`) | 2,114 | |
| + padding boundaries | **2,116** | 12 uncheckable, 2 whitelisted, **0 unexplained** |

- **Uncheckable (12).** 8 static functions whose start is exact but whose size the reference cannot state, and 4
  extra starts inside objects where several statics share one interval (env.o 2, leointerrupt.o 1, xldtob.o 1).
  The counts match the number of statics the grader could not place. They are reported apart and not counted as
  agreement.
- **Whitelisted (2).** `handle_CpU` in handwritten exceptasm.s is entered only by a `beq` from `__osException` and
  branches back into it. Its glabel is an authoring choice that no binary fact supports. It is one fact, and it shows
  up twice: as a missed start, and as `send_mesg` being 52 bytes long.
- Seeding the wrong way was worse than not seeding. A plain `addFunction()` seed fell to 2,104 because it displaced
  spimdisasm's trusted jal symbols.

## Grader findings (reference side)

- IDO `static` functions never reach the linked ELF, and object symtabs list only some of them as sized `*UND*`
  entries. Statics come from uncovered intervals: 16 placed, 3 objects with shared intervals.
- 9 of 107 multi-function objects are laid out in exactly reverse source order (libultra env.c among them). That is
  why source order cannot place statics. The cause is not established; catalogued as a review pattern.
- The grader declined silently twice while being written: a source-path suffix bug read zero files, and a register
  name compared as `"<RegGprO32: sp (29)>"`. Both now have fire tests.

## Not covered

Overlays and DMA-loaded segments, data typing/jump tables/strings/.rodata ownership, compiler fingerprinting, asm
emission in the pipeline's format, the round-trip ROM rebuild oracle, and any game besides SBK1.
