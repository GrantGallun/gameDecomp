## What changed

`eval.intake_probe` now offers bounded composition with `--repair-rounds 3 --repair-budget 12
--repair-beam 3`. Existing owners are revisited on retained alternatives; source and
action/source deduplication prevents cycles. Every distinct child is compiled and logged.
The public incumbent remains protected while lower-scoring or partially repaired alternatives
can be explored. Candidate sources, hashes, parent edges, owner declines, and budgets remain
in the receipts. The normal single-pass mode remains available.

The cast fixer can return a partial only to an opted-in caller, and only after a complete
original observation and a strict measured error reduction. Other normalization callers keep
their passing-frontend-only contract. The CLI forwards parent IDs and action metadata through
the actual SQLite attempt logger, rather than preserving lineage only in a JSON trace.

`eval.intake_blockers` separates compiler admission from object mismatch. Its frontend view
includes specific operation classes, file-aware diagnostic sites, conditional owner routes,
and actual action outcomes. Its object view reuses `solver.signals` and preserves the raw
diffs. Categories overlap; neither diagnostic counts nor class counts are repair distances.
The old 478-error unclassified bucket falls to 11 on the refreshed baseline, and four after
repairs. This reclassification itself is not a solver gain.

Review caught a failed include appearing as a rejected frontend with zero structured errors.
Located header/fatal errors are now parsed; fatal, unmatched, and failed-zero-error reports
are marked incomplete and cannot win the error-count ranking. Header locations are never
shown as candidate source excerpts.

## The exact match came from the object diff

The matrix candidate already passed both compilers at 95.865 similarity. Its target and
candidate contained the same instruction multiset, with a load scheduled across adjacent
stores differently. Swapping the generated byte-view stores at offsets `0x20` and `0x1C`
produced a byte-exact object. No field offset was changed.

The existing statement-order parser did not recognize these byte-view lvalues. The new
`solver.byte_view_order` generator is wired into the common `solver.rewrites.propose` catalog.
It requires a pure instruction-order residual, witnessed word-store offsets, adjacent stores
sharing a source base, and a narrow zero-fill/computed-word pair. Volatile expressions,
calls, updates, assignments, and unbraced control headers decline. These are hypotheses;
alias independence is not asserted and the compiler certificate remains authoritative.

The automatic catalog replay examined all 40 compiled mismatches. The new generator fired
on the matrix function, proposed three candidates, and reached exact in **two compiler
attempts**. A separate replay of the eight candidates above 95 similarity independently
reproduced that exact match through the same catalog.

The existing object generators also improved `updateRaceCoursePropModels` from 98.556 to
98.667 and `releaseMenuAssetHandles` from 98.269 to 98.462 without reaching exact. Exploratory
byte-unit hypotheses moved the former to 99.667; those manual probes are separately recorded
and are not credited as an automatic repair. Its remaining diff concerns register choices.

## What still blocks progress

After repair, 156 candidates lack at least one compiler pass, 39 pass both compilers but
do not match, and five are object-exact. The largest remaining frontend groups are:

| Observed operation | Affected functions | Functions with only this reported class |
|---|---:|---:|
| Wrong call argument count | 68 | 14 |
| Declaration conflicts | 45 | 6 |
| Member access on `void` | 43 | 8 |
| Member access on a scalar or array | 42 | 3 |
| Missing member | 37 | 1 |
| Invalid binary operands | 34 | 10 |
| Indexing a non-pointer | 31 | 1 |

A sole reported class can still require several fixes. Wrong argument counts need the
callsite and evidenced prototype/ABI reconciled; indexing needs the address/array/loaded
pointer distinction recovered; the member repairs still require supported base correspondence
and width evidence. Removing their neighboring cast errors does not supply those facts.

Of the 39 remaining compiled mismatches, 38 have structural observations and 38 have register
observations; these sets overlap. The matrix case itself was coarsely tagged as both offsets
and ordering, so object profiles also remain triage aids rather than root-cause proofs.
The raw diff is necessary before choosing a repair.

The bounded search stopped at a fixed point in its retained archive on 195 functions,
immediately at an existing exact match on four, and at the 12-attempt budget on
`collidePlayerWithCourseTriggerVolume`. This is not a proof that no other source alternative
can improve any of them.
