# m2c reconstruction trials, 2026-09-30

The concrete win is preserving machine byte offsets when m2c cannot reconstruct a typed access. The final experimental adapter raises compiler **and strict frontend** acceptance from 10/12 to 12/12 on a frozen DEV sample, including 2/4 to 4/4 on the motivating sprite cluster. It produces **zero additional byte-exact matches**. It has not been connected to the production solver or KB.

## What was implemented

Installed m2c 0.1.0, upstream commit `ef8aff103d1eb6fcc4fb73be2d1f887439bcb0cb`, consumes assembly. It parses instructions, builds control/data flow, lifts expressions, infers types and prints structured C. The relevant gap occurs when a machine address addition survives as a raw `BinaryOp` after field/array reconstruction declines: attaching a structure-pointer type can give C addition an incorrect element scale. This experiment intervenes at that fallback, leaving successful reconstructed accesses alone.

`byte_address.py` represents such additions through a byte-pointer view, without using the upstream `Cast.use()` type-unification behavior. It declines scalar addition, two-pointer addition, floating offsets and already-byte-sized pointees. The final formatting hook preserves an explicit pointer view around address additions when a store destination is known late. Upstream can otherwise elide an existing cast after unifying its type even though the printed operand still uses byte pointers. These are retractable C hypotheses, not inferred field facts.

The first lifting trial used 48 compiles: four choices on four motivating sprites and eight other DEV functions chosen by size/name and observed instruction patterns before any outcomes. The first byte draft fixed IDO compilation of both sprite bodies but exposed one incompatible pointer assignment in each. A separately preregistered follow-up applied the late store view to all 12 original functions, using 12 additional compiles with the original baseline sources as parents. It passed compiler/frontend checks for all 12. The other ten functions have unchanged C and equivalent object sections; the eight transfer functions did not exercise a new byte-address fallback, so this does not establish broad transfer benefit.

`provenance.py` is an opt-in observer with bounded storage and hooks restored on exit. Its links mean an instruction wrote an expression value to a register, plus observed expression child relationships. They do **not** establish complete creation origins or full transitive provenance through memory, control flow and phis. Type hypotheses are labeled separately as mutable. Source paths, line numbers, hashes, original instruction text and available address/word comments are retained. The final export handles the repository's five-digit file-offset annotations; older exports preserve those original lines but did not extract their address fields. Graphs may contain cycles. Every export is training-ineligible, and observer faults/caps are explicit.

## Feedback and execution limits

The original finite execution check mistakenly submitted an assembler `nonmatching` macro to the instruction interpreter. It also ranked unavailable/inconclusive execution as zero disagreement. Both mistakes were confined to this experimental harness; its selector was never deployed. The original results are preserved. `feedback.py` rechecks the 46 compiled first-trial objects against the compiler's normalized target disassembly and refuses to treat missing execution as success. A smaller textual diff remains a diagnostic, not a correctness measure.

The final follow-up uses normalized target disassembly directly. Both repaired sprite bodies pass six synthetic cases apiece; `Flength` and `approachRaceIntroFlyoverSpinStep` do too. Other functions have incomplete cases because random synthetic globals can produce unmapped accesses, and wrappers with calls lack a specified callee environment. These cases do not demonstrate coverage of the repaired address paths, valid game-state domains or universal equivalence. They justify no functional acceptance or replacement of original build-path assembly. The motivating fixtures independently demonstrate that the adapter fires on the bad stride fallback and preserves recovered word-array indexing.

## Recommended next work

First turn byte-address fallback into a separately tested candidate generator, retaining the ordinary draft and admitting a candidate only through the existing byte-exact certificate and frontend gates. Expand the positive sample to other unresolved address expressions and valid entry states before promotion. Record each view's expression/witness identity and rejection reason so it remains explainable and retractable.

Next use the provenance sidecar to connect a compiler residual to the actual lifted expression and observed instructions, rather than repairing C by guessed source text. This trial exports that substrate; it does not yet implement automatic residual-to-expression repair or complete provenance coverage.

Keep joint inference as a bounded optional hypothesis source. m2c already supports it; its declaration refinement is useful evidence to inspect, but these results give no reason to make grouping the default. Further control-flow choices should be chosen from an identified residual and validated entry-domain coverage, rather than widening a search because a text diff is shorter.
