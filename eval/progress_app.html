How the campaign runs

Follow the mint path for a typical resumed fast-campaign repair. A work item is one function and one selected profile; the controller repeats until its work budget, queue, or pause boundary is reached. Amber work is conditional. Blue work has its own entry point.

Main campaign loop

Repeat for each work item

1 · Select

Project the repair queue from saved function states and evidence. Select a function and its next profile.

fast_campaign.run → repair_queue.project → completion_campaign.scheduled_profile
↓

2 · Dispatch

Verify frozen inputs, isolate the function workspace and worker database, then submit the job.

fast_campaign.run → campaign_workers.isolate / synchronize → worker
↓

3 · Generate and repair

The selected profile enters the campaign executor. A normal repair visit tries bounded deterministic actions and, when budgeted, model edits. Other profiles may take specialized paths.

completion_campaign.execute → agentrepair.run → modelrepair.search
↓

4 · Measure every candidate

Compile with the target recipe, run the project C frontend, compare the object and relocations, and log the attempt. A similarity score alone is not an exact match.

workspace.score → frontend_check.check → byte_certificate → kb/attempts
↓

5 · Import and checkpoint

Merge the private attempts, accept the best source and retained alternatives, update queue state, and save a resumable checkpoint.

campaign_workers.merge → completion_campaign.accept → campaign_state.Store.save
↺ Next eligible work item

Feeds the loop

Campaign launch and restart

The supervisor runs bounded batches and resumes from the durable checkpoint. The dashboard reads that state; it does not choose candidates.

campaign_service.supervise → fast_campaign.run

Initial intake

Before fast repair can run, the completion campaign builds function workspaces and drafts C from binary inputs and allowed context. Fast dispatch requires completed intake.

completion_campaign.run → _intake → m2c_context.seed_variants

Read-only evidence and context

Target assembly, compiler settings, headers, and KB observations guide proposals. Inferences remain retractable; held-out source is excluded.

solver/workspace.py · solver/compiler_recipe.py · kb/

Beside or after the loop

Semantic feedback · conditional

Compiling candidates can receive target-versus-candidate execution feedback. Sampled agreement guides repair but does not certify byte equality.

agentrepair.run → semantic_lane.DeferredPanel

Integration and captures · after drain

When enabled, a drained fast campaign checks exact replacements in a disposable full build and runs planned runtime captures. These have separate receipts.

campaign_integration.sweep · campaign_runtime.sweep

Separate experiments

Compiler research, adapter training, narrow RSI, differential wavefront, and older solver orchestration have separate entry points. Starting the campaign does not automatically run them.

eval/research_control.py · eval/training_control.py · eval/rsi_control.py · eval/differential_wavefront.py · solver/pipeline.py

Local experiments

Adapter training

Connecting

A separate, explicit action: one bounded source-repair LoRA run. It is not part of the research loop and it changes nothing until an adapter passes a separate held-out evaluation.

Hard ceilings: 20000 steps, 480 minutes, 200000 examples. Runs stop at the first limit. Stop terminates the trainer and its compiler subprocesses as one process group. There is no automatic restart and a dashboard restart adopts a live run instead of resetting its counters.

Narrow-RSI experiment

Connecting

One bounded parent → candidate loop: freeze the parent, research a hypothesis, verify and assemble it, train, evaluate against a frozen panel, then accept the candidate or keep the parent. It reuses this dashboard's worker supervision and its own declared ceilings.

Start launches one runner in the background and refuses a second copy while one is running. Stop writes STOP in the run directory and signals only that run's own recorded process group; it never touches other WSL, campaign or GPU jobs.
